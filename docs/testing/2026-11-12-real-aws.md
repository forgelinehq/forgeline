# Real checks on AWS and the Pi, 2026-11-12

What was run against real services on the maintainer's Raspberry Pi Forgeline (OpenTofu 1.13.9, AWS provider 6.7x,
region ap-south-1), what it showed, and what was cleaned up. Account numbers are masked in every picture and log.
Proposals were made by the `claude-agent` test user and approved by a second principal (the server token), with the
maintainer's go-ahead; the first removal was approved by the maintainer.

## 1. Removing what a blueprint built (note 041)

A free test blueprint: a queue, a table, a versioned bucket and a log group.

## Found and fixed

- Cloud changes and AI proposals were listed in random order (their ids are random), and only a random 100 were
  shown once there were more. They are now newest first.
- Watch › Services waited for the full account summary before drawing; it now draws at once.
- A step-1 removal title said "and remove the rest (0)".
- A blueprint could not be deleted after everything it built was removed (fixed the same day).
- A preview said "ready" for an agent the account's quota could never allow; it is now denied with the reason.
- A source repository's push role needed an extra IAM permission, could not be taken by GitHub's current token
  subjects, and failed with its error hidden; all three fixed.
- After a preview was applied, the canvas still showed its "+ add" marks and offered to send it again; it now says the
  blueprint was built since that preview.

## 6. An agent on Bedrock AgentCore

An arm64 test agent (it answers `/ping` and `/invocations`, writes to its linked table and calls a Bedrock model) was
built on the Pi and pushed to a temporary ECR repository; a blueprint ran it as an Agent block linked to a table.

The execution role, its policy and the table were created, then AWS refused the runtime:

```text
ServiceQuotaExceededException: maxAgents limit exceeded for account <account>.
```

The account's Bedrock AgentCore quota **Total Agents per Account is 0** (AWS's default is 1000), so no agent can run
until AWS raises it. Forgeline kept the state of what the failed apply made, and removal took it away (two steps), with
the temporary image repository deleted afterwards:

```text
preview: ready unprotect add=0 change=1 remove=2 [] 
succeeded | Remove blueprint Check: AgentCore agent, step 1 of 2: turn off deletion protection (1 to change) and remove the rest (2) | Applied: 0 added, 1 changed, 2 removed.
{"applies":2,"aws_account":"<account>","built":true,"region":"ap-south-1","updated_at":"2026-11-12T09:50:12.197663721Z","updated_by":"token"}
preview: ready all add=0 change=0 remove=1 ['warn:deletes-data'] 
succeeded | Remove everything blueprint Check: AgentCore agent built, data included (1 to remove) | Applied: 0 added, 0 changed, 1 removed.
{"applies":3,"built":false,"removed":true,"updated_at":"2026-11-12T09:50:40.44956298Z","updated_by":"token"}

## After removing the AgentCore test (prefix fl-cd32e9) and the temporary image repository

tables fl-cd32e9*: 0
```

The preview now reads that quota and denies a blueprint that adds more agents than the account allows, so this is
caught before anyone approves.

Checked on the Pi after the fix was deployed, with a preview only (nothing built, the test blueprint deleted after):

```text

```

## 7. An app built from GitHub and deployed through Forgeline

A temporary private repository (a two-line Dockerfile and a page) and a blueprint whose app named it as its source.

1. The blueprint made the app's private image repository and the push role (13 added; the app at 0 tasks).
2. Forgeline's suggested workflow was added to the repository unchanged. Its first run was refused by AWS, which showed
   two bugs, both fixed the same day and deployed before the next try:
   - the role's trust named GitHub's provider through a lookup that needs `iam:ListOpenIDConnectProviders` (the preview
     failed), and the failure message hid the error behind the plan listing;
