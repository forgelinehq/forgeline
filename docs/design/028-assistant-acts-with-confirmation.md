# 028: The assistant acts inside Forgeline, with a Confirm card

Status: **Decided 2026-11-04; slice 1 (save a pipeline, start a run) is built.**
Builds on notes 013 and 024 (assistant and its stream), 026 (access policy), 027 (memory) and 006 (cloud changes).

## Question

The assistant can only read, so it explains and never helps. People want to say "set up CI for this repo" or "run it" and have
it done. How does it act without a mistaken, or injected, request changing things on its own?

## Decisions

| Decision | Choice | Why |
| --- | --- | --- |
| Who acts | The server, as the **person**, when they press Confirm. The model only prepares | The model reads logs and names other people wrote; it must never be the one that decides |
| What the person sees | A card with the effects **generated by the server from the file** (each step's image, network, secrets) and the whole file | A summary written by the model could hide a secret or an open network |
| Limits | Owner only (an administrator gets 404), once (409 after), 30 minutes, 10 waiting per person, the file is checked again at Confirm | A card is a single-use capability, not a standing permission |
| Where | A person chatting only: not agents, not MCP clients, not plain `/chat`, not viewers | Somebody has to be there to press the button |
| Cloud | Not in this tool. Cloud changes stay proposals approved by a different administrator (006) | Principle 5 |
| Audit | `assistant.action.prepare`, `.confirm`, `.dismiss`, plus the usual `pipeline.create` and `run.start` | The log shows who pressed what |
| Memory | Preparing counts as reading data, so a note saved in the same turn is held for confirmation (027) | Same rule as any lookup |

## Use cases this serves

| Ask | How it is answered |
| --- | --- |
| "How are things?" / "What needs me?" | `morning_check` reads the host, failed runs, waiting proposals and worst findings in one lookup |
| "Set up CI for my repo" | `github_repos`, `github_files` to see what the project is, then a `save_pipeline` card, then a `run_pipeline` card |
| "Why did that fail, and what now?" | the run lookups already there, then a card or a proposal |

Reading a repository is read only and limited to the allow list, the default branch and 12 KB a file. Files named like secrets
(`.env`, keys, `.pem`, `.netrc`) are never read and known secret shapes in other files are replaced with `[hidden]`. Repository
text was written by other people, so a turn that read it counts as dirty for memory (027).

## Not in this slice

Updating or deleting pipelines, cancelling runs, connecting integrations, adding people and changing settings. Each becomes
another action kind with its own effects text and a test that removes its check. Settings that widen access (people, roles,
policy) should need an administrator to confirm and never be preparable by a developer.

## Checked

Go tests through the real server: nothing exists before Confirm; another person (and an administrator) gets 404; a second
Confirm, a dismissed card and an expired card get 409; an invalid or duplicate pipeline gets no card; a run starts only after
Confirm; the tool is neither offered nor run in plain chat or for an agent; the eleventh waiting card is refused. Seven rules
were removed one at a time and each failed a test.

Not checked: how well a real model decides when to prepare an action; the card on a phone.
